关于本系统

后台管理系统

产品定位

本后台是 EMRS(智病历 AIS) 的 医院侧管理工具,与小程序并行运行。
服务对象是:医院管理员 / 科室主任。
主要职责是:建档(组织、职位、人员、组件库、药品字典)、核口径(组件字段约束)、补缺口(待分配队列、待分配护士)、看大盘(本院运转全景)。

后台 不 处理诊疗活动,不写处方、不读 PACS / LIS、不发出院小结。

设计原则

0.0 可回放
所有数据存在浏览器本地 mock 里,
关页面即重置。便于演示。
不写死
职位字典、组件字段、标准范围、组件图标,
全部可编辑。
不替医生决策
医生个体目标范围在医生小程序端设置,
后台只读,不替代。
不写处方
药品库只作字典,
所有处方由 HIS 负责。
只软删除
字典 / 组件 / 字段 全部停用,
不物理删除。
所有链接可点击
每个 href 真实存在一个 .html 文件,
走通完整流程。

本期范围(Q1)做什么 / 不做什么

在做 ✅

  • 组织架构(医院 / 科室),含科室主任唯一性
  • 职位字典(行政 / 技术职称 / 其他)可增删改
  • 工作人员建档 + 微信扫码入队列 + 认领 / 归档
  • 二维码中心(医院邀请码 + 医生患者码)
  • 任务组件库(字段定义:字段名 / 字段类型 / 标准范围 / 是否必填)
  • 病患列表(归属 + 医生个体范围来源只读)
  • 药品库(字典,不作处方依据)

不在做 ❌

  • 权限矩阵(本期用种子账户分组模拟)
  • HIS / PACS / LIS 真实对接(全部 mock)
  • 电子签名 / CA 认证
  • 移动端 App(本期只做 H5 + 微信小程序)
  • 处方录入 / 审方 / 调剂
  • 病历文书录入(Q1 前台只做任务中心,文书留 Q2)

数据存储

演示数据落在 assets/back-data.js, 包括:
· 2 个医院:H 市第一医院(运营中)、H 市中医医院
· 5 个科室:神经内科 / 神经外科 / 急诊科 / 康复医学科 / 神经内科@H2
· 9 个职位(3 类:行政职务 / 技术职称 / 其他)
· 11 名医护人员(含 1 名已停用)
· 5 名待分配的微信扫码用户
· 7 名病患(含 1 名个体目标已过期)
· 8 个任务组件(含 1 个自定义字段演示)
· 11 种药品(含 1 个停用)

真实病例取自档案 (陈丙英·81岁·女,4 次住院), 其余字段为演示需要,均经脱敏 + 不展示真实人名。

反馈与协作

· 字段 / 数值口径 / 临床规则 → 联系 临床专家(clinical-expert);
· 视觉细节 / 配色 / 组件 → 联系 UI 设计师;
· 流程问题 / 闭环缺失 → 在本 Demo 上直接点一遍路径,把卡住的一步告诉 PM。
